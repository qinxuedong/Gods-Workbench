# Provider 协议边界说明

- **状态**：CURRENT / CONTRACT SUPPORT
- **适用范围**：`gw/` 中显式声明的外部 Provider 适配器与吞吐观测
- **定位**：说明协议边界、失败语义和安全验收边界；不是 Provider SDK、凭据配置或真实服务可用性证明。

## 1. 适配器边界

- 每个上游协议必须使用显式、可审计的适配器名称；不得根据模型名称猜测协议。
- 当前视频适配器协议名为 `newapi_video`。适配器只负责把本地任务映射到已声明的上游协议，不把任意供应商响应伪装成统一成功。
- Provider 地址、认证方式、超时和能力必须来自运行配置；仓库不保存真实凭据，不把测试配置当生产配置。

## 2. 视频任务协议

当上游声明兼容该协议时：

- 创建使用 `POST /v1/video/generations`，请求至少明确 `model`、`prompt` 以及已启用的时长、尺寸、帧率和元数据字段。
- 查询使用 `GET /v1/video/generations/{task_id}`。
- 上游任务状态至少区分 `queued`、`in_progress`、`completed`、`failed`；成功响应必须提供可验证的产物位置和必要媒体元数据，失败响应必须保留可分类错误。
- 本地任务 ID、上游 `task_id` 和最终本地产物 URL 不得混为同一字段。

## 3. 失败、超时与幂等

- 上游没有明确取消或幂等保证时，本地取消只撤销本地等待/发布，不得宣称远端任务已取消或费用已撤销。
- 创建超时视为“结果未知”，禁止自动重发可能计费的创建请求；已有上游 task_id 时仅允许恢复查询，查询超时不等于任务失败或获得重新创建的许可。本地幂等键不代表上游幂等保证。
- 不因 2xx、存在 URL 或模型名称自动判定业务成功；业务验收必须有断言和独立复核。
- Provider 不可用、配置缺失、协议字段不完整或状态无法识别时，显式返回降级/失败状态，不伪造默认产物。

## 4. 产物与凭据安全

- 上游 Bearer 或其他凭据只发送到已配置的 Provider 端点，不自动转发给产物域。
- 产物 URL 必须经过域名/协议/大小/超时等安全校验，并在有界下载后落本地。
- 下载后的媒体必须经过 `ffprobe` 结构校验；对外只返回本地鉴权内容 URL。
- 日志只记录任务标识、状态、错误类别和摘要，不记录 Token、Cookie、授权码或完整响应凭据。

## 5. 吞吐与观测

- Chat Completions 等协议只使用上游明确报告的 `usage.completion_tokens` 计量输出 token；必须是非负整数且不是布尔值，缺失或其它类型均视为不可计量。
- 端到端耗时使用单调时钟；指标名称必须明确是请求端到端输出 tokens/s，不得冒充流式解码速度。
- 观测数据必须区分 Provider 报告值、本地测量值和推断值；不可测量时返回明确原因。

## 6. 验收边界

- 协议契约测试只能证明字段映射、错误处理和安全边界；测试服务通过不证明真实商业 Provider 可用。
- 真实 Provider 验收需要独立配置、授权、现场读回和当前提交 SHA 绑定；本仓不默认执行付费生成、不提交真实任务。
- 任何新 Provider 必须新增协议边界、能力矩阵、失败语义、凭据处理和定向测试；不得把未审协议写入通用回退路径。
