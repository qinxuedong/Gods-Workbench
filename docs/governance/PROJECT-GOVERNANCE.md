# Gods-Workbench 项目治理指南

- **状态**：CURRENT
- **适用范围**：本仓库后续功能、修复、测试、文档、发布和数据操作
- **目标**：把对未来项目仍有价值的治理规则收敛为一份可执行指南；历史任务日志、阶段报告和旧仓材料不进入本仓。

## 1. 权威边界

1. Git 工作树、提交、分支和当前测试结果是代码事实；治理文档是规则与决策记录；聊天或代理报告不能覆盖代码和测试实物。
2. 新仓只接受已审核的行为规范、接口契约、黄金夹具和经过解耦审查的自有切片。不得复制旧仓源码、提交历史、知识材料或未审第三方制品。
3. 当前发布状态固定为 `NOT AUTHORIZED FOR PUBLIC DISTRIBUTION`；`/healthz` 的 `release_authorized` 必须为 `false`。
4. `docs/behavior/`、`docs/contracts/`、`docs/fixtures/` 是运行与验收输入；设计与治理规则以本仓整理后的总文档为准；其他历史文档不自动进入新仓。

## 2. 变更流程

1. 先写清目标、范围、影响面、回滚方式和验收证据。
2. 需要破坏性操作、文件删除、外部写入、远程创建或发布时，先取得明确人工授权。
3. 按文件所有权拆解任务；不得使用 `git add -A` 覆盖或带走无关改动。
4. 实施后先跑定向测试，再跑 `pytest -v`；收集错误、跳过和失败必须原样记录。
5. 最终结论必须由独立复核绑定当前 HEAD 与未提交差异/文件哈希；历史 CI、源仓测试或局部绿灯不能替代当前新仓证据。

## 3. 测试与契约门禁

- 黄金夹具和防污染卫生测试必须通过，才能作对应验收声明。
- 401 表示未认证，403 表示权限不足，409 表示 CAS 冲突；错误包外层统一为 `detail.code` 与 `detail.message`。
- 项目编辑、归档、回收站操作和画布拓扑更新携带 `expected_version`，禁止静默覆盖。
- 智能画布任务返回 202、稳定 `job_id` 与 `poll_hint`；普通拓扑和智能编排统一归属于 `god-canvas`。
- 测试态每例使用临时目录；不得读取真实用户数据。测试、开发、生产三态的数据库、视频目录和 Cookie 必须隔离。
- 定向测试结果只能证明定向范围；全量收集失败时不得改称“全量通过”。

## 4. 数据、安全与依赖

- 核心 ID 统一为 `project_id`、`canvas_id`、`entity_id`、`job_id`、`asset_id`。
- 开发数据只写 `.local/runtime-dev/`；生产数据只写 `%LOCALAPPDATA%\GodsWorkbench\`；生产数据不得进入源码仓库。
- `--reset` 只能清理显式指定且位于开发沙盒内的目标；不得删除用户数据或生产数据。
- 迁移默认只复制获准的 `data/` 和 `auth/auth.sqlite3`，不搬临时视频；失败不生成成功回执，原数据保留。
- 依赖使用哈希锁；不新增外部 CDN、框架、构建链、二进制或未审第三方资源。
- 不保存凭据、Cookie、授权码、真实用户数据或未脱敏密钥；日志和证据只记录必要的摘要。

## 5. 文档准入与证据

- 行为、契约、夹具文档描述“应该怎样”；代码和测试证明“当前怎样”；两者冲突时必须记录差异，不得默默改写证据。
- 新增治理文档必须注明状态、范围、来源、验证方法和回滚方式。
- 阶段报告、代理简报和历史审计只能作为参考或封存证据，不能自动成为运行规则。
- 来源、许可证、第三方、隔离提示词和旧仓知识材料必须单独通过准入，不得用文件存在、哈希或数量一致代替授权。

## 6. 发布与远程

- 未取得明确授权前，不创建 Git remote、不推送、不公开发布、不添加正式开源许可证。
- 远程 CI 必须绑定当前提交 SHA 读回；本地通过不等于远程 CI 通过，远程 CI 通过也不等于生产验收或发布授权。
- 发布前必须完成独立审计、当前 SHA 测试、二进制/路径卫生、许可证和来源核验，并保留可回滚提交。

- 规则变化同步更新本指南、AGENTS、相关契约和测试；不要通过复制旧报告制造“完成”状态。
