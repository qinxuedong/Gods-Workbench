# 项目中心行为规范 (Projects Hub Behavior Specification)

- **状态**：CURRENT / FROZEN_BASELINE
- **适用范围**：项目中心（Projects Hub）项目管理、排期持久化、上下文流转与生命周期控制
- **约束**：无旧源码复制、无旧变量/DOM 复制、零用户数据；严格贯彻 CAS 版本控制与统一错误语义
- **发布状态**：**NOT AUTHORIZED FOR PUBLIC DISTRIBUTION**

## 1. 范围与目标

本规范定义 **v2 production projects hub** 的外部可观察行为，不定义任何实现细节。覆盖：

- 项目列表读取、筛选、搜索
- 项目创建、编辑、归档、恢复、回收站流转
- 项目排期输入、日期持久化与跨页面项目上下文
- 真实路由导航与工作台入口
- 空状态、加载状态、错误状态
- 权限边界与并发冲突语义

## 2. 角色与权限边界

- 匿名用户：读取受限，写操作应返回认证或授权错误。
- 普通成员（具备项目写权限）：可创建/编辑项目；无治理权限时不得归档或恢复。
- 治理成员（具备治理权限）：可执行归档、移入回收站、恢复等生命周期操作。

## 3. 数据与状态模型（行为层）

每个项目至少包含：

- 稳定标识：`project_id`
- 展示字段：名称、类型、阶段、摘要（可为空）
- 生产统计：场次数、镜头数、进度（0-100）
- 排期字段：开始时间、截止时间（时间戳持久化）
- 生命周期字段：活跃 / 已归档 / 回收站
- 并发字段：版本号（用于 CAS）

## 4. 关键行为

### 4.1 列表与筛选

1. 默认进入“活跃项目”列表。
2. 支持切换“活跃 / 已归档 / 回收站”作用域。
3. 支持按项目类型筛选，并与搜索条件叠加。
4. 切换作用域后，计数与列表同步更新。

**验收语义**

- 任何筛选切换都不应污染当前已选项目上下文。
- 当结果为空时，必须显示明确空状态，不得渲染陈旧列表。

### 4.2 创建与编辑

1. 创建最小必填项：名称；可选项包括类型、描述、排期。
2. 编辑时可更新元信息与排期，提交必须携带 `expected_version`。
3. 成功后列表即时反映新数据，并更新当前项目上下文。

**验收语义**

- 创建成功后，新项目应可立即作为导航上下文传递到工作台。
- 编辑失败时保留用户输入，不得“成功样式失败”。

### 4.3 生命周期治理

1. 归档：将活跃项目转为只读治理状态。
2. 回收站：仅允许已归档项目移入回收站。
3. 恢复：支持从已归档恢复为活跃，或从回收站恢复为可见项目。

**验收语义**

- “删除”语义为逻辑隔离（回收站），不是物理删除。
- 对版本不一致提交返回冲突错误并提示刷新后重试。

### 4.4 排期与日期持久化

1. 日期输入支持选择开始与结束。
2. 日期持久化采用时间戳，不因本地时区切换丢失顺序关系。
3. 允许仅有开始时间；若结束时间早于开始时间，系统应自动纠正或阻止提交。

**验收语义**

- 重新打开编辑后应能回显已保存的排期。
- 无效日期不得写入后端。

### 4.5 路由与工作台导航

1. 从项目中心可进入多个工作区域（如工作台、制片、故事板等）。
2. 导航时必须携带当前 `project_id`，保证跨页面上下文一致。
3. 壳层路由加载失败时，必须回退到整页导航，不能卡死在半加载状态。

**验收语义**

- 切换页面后仍可识别当前项目。
- 导航失败时用户可继续操作，不出现不可恢复空白页。

### 4.6 空/加载/错误状态

- 加载中：显示可见加载反馈。
- 空状态：显示“无数据或无匹配结果”。
- 错误状态：显示可定位错误（网络、权限、冲突、参数错误）。

## 5. 错误语义（接口消费层）

- `401 Unauthorized`：未认证，前端应提示重新登录或会话失效。
- `403 Forbidden`：无权限，前端应提示权限不足且禁用对应操作。
- `409 Conflict`：CAS 版本冲突，前端应提示刷新并重试。

## 6. 非目标

- 不定义视觉风格、动画、DOM 结构和 CSS 细节。
- 不定义任何旧仓库实现命名与文件级映射。
